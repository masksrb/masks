_Clients_ are consumers of the masks server. Typically they are web or mobile
apps that manage data only meant for authenticated actors. For every
_real-world_ client there will be a corresponding record in the masks
server.

## Adding clients

You can add clients manually as a manager, via the API, CLI,
with seeds, a `clients.yml` file, or a number of other ways.

### `clients.yml`

Any clients specified in `clients.yml` will be available to masks:

```yaml
mobile:
  name: My mobile app
  type: public

admin:
  name: Admins only
  type: internal
  scopes:
    required: admin
```

Refer to [the settings](#settings) for a complete set of options.

### Command line

You can also make new clients using the command line. The following adds a
client with a key of `my-app` named `"My app"`:

```sh
masks client my-app name="My app" type=confidential
```

You can also edit clients, given a key:

```sh
masks client my-app allow_sso=false
```

### Ruby API

You can seed clients in Ruby with the `Masks` global:

```ruby
client = Masks.clients.new(key: "my-app", type: "confidential")
client.save
```

Or in your `db/seeds.rb`:

```ruby
#db/seeds.rb
Masks.seed { client "my-app", type: "confidential" }
```

### HTTP APIs

If configured, masks can expose a _dynamic client registration_ endpoint. Given
a valid token, a masks consumer can register clients over the network. There are
[GraphQL mutations](/reference/graphql/mutations) for adding and editing clients.

## Types

You'll notice most examples specify a `type`. Types are optional, since they are
just named defaults. There are several built-in types:

<div class="mt-3">
  <ClientTypes types={frontmatter.json.types} client:only />
</div>

You can add custom types if necessary using the `client_types` key in
your `masks.yml`:

```yaml
#config/masks.yml
client_types:
  my-type:
    internal: true
    allow_second_factor: false
    # etc...
```

<Aside type="tip">
  _**Internal** clients_ expose tokens via cookies and the session, where other
  types would expose authorization codes, access tokens, or ID tokens (as JWTs)
  in the redirect URL.
</Aside>
