---
title: Event streams
description: Send each event a tenant records to an HTTPS endpoint, signed so the receiver can verify it.
---

An event stream posts each event a tenant records to an HTTPS endpoint as it happens.

- A security team can use it to collect events in a SIEM (security information and event
  management system), a tool that gathers security logs in one place.
- Manage streams in `/manage`: open **Settings**, then the **Activity** tab, then **Streams**.
- You can also manage them through the [manage API](/reference/manage/).

## Create a stream

A stream has these parts:

| | |
| --- | --- |
| `key` | A short ID for the stream. |
| `name` | A name for people to read. |
| `url` | The address of the HTTPS endpoint that receives events. |
| Signing secret | Signs each delivery so the receiver can verify it. |
| `actions` | Optional. The kinds of event to send. An empty list sends every action. |
| `organization` | Optional. An organization's key. When set, the stream sends only that organization's events. A customer's activity can then go to that customer's SIEM. |

`createEventStream` and `rotateEventStreamSecret` return the secret once. It cannot be read again.

```sh
curl -s "$MASKS/manage/graphql" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"mutation { createEventStream(key: \"siem\", name: \"SIEM\", url: \"https://siem.example.com/masks\", actions: [\"session.started\", \"actor.deleted\"]) { secret } }"}'
```

Other mutations act on a stream once it exists:

- `testEventStream` sends a `stream.tested` event and reports what the receiver answered.
- `archiveEventStream` stops delivery.
- `restoreEventStream` starts delivery again.

## What is sent

Each event is a `POST` request with a JSON body.

| Field | Meaning |
| --- | --- |
| `id` | The event's ID. Also sent as the `Masks-Delivery` header. |
| `tenant` | The tenant's subdomain. |
| `action` | The action, such as `session.started`. Also sent as the `Masks-Event` header. |
| `created_at` | When it happened, in UTC. |
| `actor` | The UUID of the account it happened to, or null. |
| `by` | The UUID of the account that did it, or null. |
| `client` | The `client_id` involved, or null. |
| `organization` | The key of the organization the event belongs to, or null. |
| `ip_address`, `user_agent` | Where it came from. |
| `details` | Fields specific to the action. |

How delivery works:

- Any response with a status code from 200 to 299 counts as delivered.
- Each event is delivered at least once, so the same event can arrive more than once.
- Events can arrive out of order.
- Use `id` to throw away a repeat.

## Verify a delivery

Each delivery has a `Masks-Signature` header. It reads `t=<unix time>,v1=<hex>`.

- `t` is the timestamp.
- `v1` is an HMAC-SHA256 of the timestamp, a period, and the raw request body. It is keyed with the
  stream's secret and written in hexadecimal.

To verify a delivery on the receiver:

1. Recompute the HMAC-SHA256 from the timestamp, a period, and the raw request body.
2. Compare it with `v1` in constant time.
3. Reject the request if its timestamp is more than five minutes from the current time.

## Failures

A delivery that gets no response from 200 to 299 is tried up to eight times. The wait between tries
grows each time.

- After the last try, masks records a `stream.failed` event. This event is never streamed.
- The stream's `lastFailure` shows the latest error.
- The stream's `lastDeliveredAt` shows the latest success.

## What masks refuses

- An address that does not use HTTPS.
- An address that includes a username or password.
- An address that resolves to a private, loopback, or link-local address. These are addresses inside
  a private network, on the same machine, or on the local network link. masks checks this when the
  stream is saved, and again on every delivery.
- An action masks does not record.
