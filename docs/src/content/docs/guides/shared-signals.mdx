---
title: Shared signals
description: Tell another system when a session ends or a credential changes, and act on the same events from a provider, using the OpenID Shared Signals Framework.
---

masks tells other systems about security events as they happen, using the Shared Signals Framework
(SSF). SSF is an OpenID standard for sending security events between systems.

masks works in both directions:

- **As a transmitter**, masks sends events out. A receiver registers a stream, and masks pushes it
  a signed security event token when a session is revoked, a credential changes, or an account is
  suspended. The receiver can then act before the affected tokens expire.
- **As a receiver**, masks takes events in. A provider that actors sign in with can tell masks to
  sign someone out. See [receiving signals from a provider](#receiving-signals-from-a-provider).

A receiver is the system that gets the events. A stream is the receiver's subscription: where to
send events, and which ones.

## Register a receiver

A receiver is a confidential client that signs in as itself. A confidential client is one that can
keep a secret.

1. In `/manage`, add a client with the `client_credentials` grant.
2. Add `masks:signals` to its allowed scopes.
3. Have the receiver request a token with `grant_type=client_credentials` and
   `scope=masks:signals`.
4. Have the receiver send that token as a bearer token to every endpoint below. A bearer token goes
   in the `Authorization` header.

A token issued to an actor cannot manage a stream.

## Find the endpoints

`/.well-known/ssf-configuration` lists the endpoints and the delivery methods.

| Field | Value |
| --- | --- |
| `issuer` | The tenant's issuer. |
| `jwks_uri` | The keys that verify each security event token. |
| `delivery_methods_supported` | `urn:ietf:rfc:8935`, push delivery. |
| `configuration_endpoint` | `/ssf/streams` |
| `status_endpoint` | `/ssf/status` |
| `verification_endpoint` | `/ssf/verify` |
| `default_subjects` | `ALL` |

## Create a stream

A receiver holds one stream. Create it with `POST /ssf/streams`:

```sh
curl -s "$MASKS/ssf/streams" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "delivery": {
      "method": "urn:ietf:rfc:8935",
      "endpoint_url": "https://receiver.example.com/events",
      "authorization_header": "Bearer inbound-secret"
    },
    "events_requested": [
      "https://schemas.openid.net/secevent/caep/event-type/session-revoked",
      "https://schemas.openid.net/secevent/caep/event-type/credential-change"
    ]
  }'
```

The response holds `stream_id`, `iss`, `aud`, `events_supported`, `events_requested`, and
`events_delivered`.

- The endpoint must be an HTTPS address on a public network.
- masks sends `authorization_header` as the `Authorization` header of each delivery.
- masks stores `authorization_header` encrypted, and never returns it.

Manage the stream with these requests:

| Request | Effect |
| --- | --- |
| `GET /ssf/streams` | Lists the receiver's stream. Returns it when `stream_id` is given. |
| `PATCH /ssf/streams` | Changes the fields in the body. |
| `PUT /ssf/streams` | Replaces the delivery, events, and description. |
| `DELETE /ssf/streams?stream_id=` | Removes the stream. |
| `GET /ssf/status?stream_id=` | Returns `enabled`, `paused`, or `disabled`. |
| `POST /ssf/status` | Sets the status, with an optional `reason`. |
| `POST /ssf/verify` | Sends a verification event that holds the `state` from the body. |

A paused or disabled stream delivers nothing. Events raised while a stream is paused are dropped.

## What is sent

masks sends events from two sets. CAEP (Continuous Access Evaluation Profile) covers sessions and
credentials. RISC (Risk Incident Sharing and Coordination) covers accounts.

| Event type | Sent when |
| --- | --- |
| CAEP `session-revoked` | A manager revokes a session or signs an actor out everywhere. An actor leaves or is removed from an organization. Their organization is archived. |
| CAEP `credential-change` | A password changes or is reset. A passkey or authenticator app is added or removed. |
| CAEP `token-claims-change` | An actor's role in an organization changes. The event's `claims` hold the new `org` claim. |
| RISC `account-disabled` | An account is suspended. |
| RISC `account-enabled` | A suspended account is restored. |

Who the events are about:

- A stream receives events only about actors who have signed in to its client, or consented to it.
- An organization's events go only to a client that has held a token for that organization.
- The subject is `{"format": "iss_sub", "iss": ..., "sub": ...}`. Here `sub` is the same subject
  the client sees in ID tokens, including a pairwise one. A pairwise subject is one that differs
  for each client.

## Verify a delivery

Each delivery is a `POST` with the content type `application/secevent+jwt`, and a JWT as the body.
A JWT is a signed JSON token.

- Its header has `typ` set to `secevent+jwt`.
- It is signed with the tenant's key from `jwks_uri`.

To check a delivery:

1. Check that `iss` is the issuer.
2. Check that `aud` is the receiver's `client_id`.
3. Use `jti` to discard a repeat.

A CAEP event holds `event_timestamp` and `initiating_entity`. `initiating_entity` is:

- `user` when the actor acted
- `admin` when a manager acted
- `system` otherwise

## Failures

masks tries a delivery up to eight times, with growing delays, until it gets a 2xx (success)
response. After the last attempt, masks records a `signal.undelivered` event.

Delivery stops when you remove `masks:signals` from the client, or archive the client.

## Receiving signals from a provider

masks also receives security events from an OpenID Connect provider that actors sign in with.

1. In `/manage`, turn on **Accept its security events** for the provider.
2. Give the provider this receiver endpoint for push delivery (RFC 8935):

```
https://acme.auth.example.com/ssf/events
```

The provider posts each event as an `application/secevent+jwt` body. masks accepts it with `202`
when all of these are true:

- `iss` is the provider's issuer, and the provider accepts security events.
- It is signed by a key in the provider's `jwks_uri`, and typed `secevent+jwt`.
- `aud` is the tenant's issuer or the endpoint above.
- masks has not seen its `jti` in the last seven days.

Otherwise masks answers `400`. The body has `err` set to `invalid_issuer`, `invalid_key`,
`invalid_audience`, or `invalid_request`, and a `description`.

### What the events do

These events sign the account out everywhere. That means every session, every refresh token, and
every trusted device. masks records each one as a `signal.received` event on the account.

| Event | |
| --- | --- |
| CAEP `session-revoked` | A session ended at the provider. |
| CAEP `credential-change` | A password or factor changed at the provider. |
| RISC `sessions-revoked` | Every session ended at the provider. |
| RISC `account-disabled` | The account was disabled at the provider. |
| RISC `account-purged` | The account was deleted at the provider. |
| RISC `account-credential-change-required` | The provider asks for new credentials. |

The account is the one connected to the provider with that subject. masks reads a subject in one
of two formats:

- `iss_sub`. Its `iss` must be the provider's issuer.
- `email`. It matches the email address the connection holds.

masks accepts other event types and subjects, and changes nothing.
