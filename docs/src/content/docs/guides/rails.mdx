## Install

```ruby
# Gemfile
gem "masks"
```

```sh
bin/rails generate masks:install
```

That mounts the engine at `/auth`, writes `config/initializers/masks.rb`, and gitignores the file
credentials land in. `--mount` puts it somewhere else; `--resource` fills in the identifier when the
app also accepts tokens of its own.

By hand, the whole of the generator's routing is one line:

```ruby
mount Masks::Rails::Engine, at: "/auth"
```

One gem carries both halves, and `Masks::Rails` loads only when Rails is already defined — the same
`gem "masks"` in a Rack or API-only app pulls in `jwt` and nothing else. See
[verifying a token](/guides/verifying).

## The routes it mounts

`client/config/routes.rb`, relative to your mount point:

| | |
| --- | --- |
| `GET /` | start the flow |
| `GET /session` | who is signed in, as JSON |
| `GET /callback` | the redirect target |
| `GET POST DELETE /logout` | |
| `GET POST /handshake`, `GET /handshake/callback`, `DELETE /handshake` | [connecting this app](/guides/handshake) |

## Configure

```ruby
# config/initializers/masks.rb
Masks::Rails.configure do |config|
  config.issuer = ENV.fetch("MASKS_ISSUER")
  config.credentials = -> { { client_id: ENV["MASKS_CLIENT_ID"], client_secret: ENV["MASKS_CLIENT_SECRET"] } }
  config.scope = %w[openid profile email offline_access]
  config.after_sign_in = "/"
end
```

`issuer` is the only value with no default. Every value also accepts a callable taking the request,
which is how a subdomain-per-tenant application points each host at its own issuer:

```ruby
config.issuer = ->(request) { "https://#{request.host.split(".").first}.auth.example" }
```

If you have no credentials to name — the usual case, since nobody should be copying a secret into an
environment file — set a `store` and let the engine [run the handshake](/guides/handshake). With
neither `credentials` nor `store`, the default is a JSON file at `config/masks.json`
(`config.credentials_path`).

`redirect_uri` defaults to `/auth/callback` on the requesting host, so it usually needs no
configuration — but it must match a URI the client was approved for.

Full list at [Configuration](/reference/configuration).

## Require sign-in

```ruby
class ApplicationController < ActionController::Base
  include Masks::Rails::Authentication

  before_action :authenticate_masks!
end
```

The concern is opt-in per controller. Set `config.authenticate_everything = true` to have the engine
include it into every controller instead; it is off by default because it lands twenty-five `masks_*`
methods on code you own.

`authenticate_masks!` returns true if there is a live session, silently refreshes when the access
token has expired and a refresh token is available, and otherwise remembers where you were headed
and redirects into the flow. An app holding no credentials yet is sent to the handshake, and a JSON
caller is answered `handshake_required`.

## Read who signed in

| | |
| --- | --- |
| `masks_signed_in?` | is there an unexpired token |
| `masks_identity` | verified id token claims — `sub`, `preferred_username`, `email` |
| `masks_tenant` | the `tenant` claim: `uuid`, `subdomain`, `name` |
| `masks_scopes` / `masks_permits?(scope)` | what the token carries |
| `masks_tokens` / `masks_access_token` | the raw tokens, for calling APIs |
| `masks_logout_url` / `masks_login_url` | |

The first four are `helper_method`s, available in views.

```erb
<% if masks_signed_in? %>
  Signed in as <%= masks_identity["preferred_username"] %>
  at <%= masks_tenant["name"] %>
<% end %>
```

## Map a tenant

masks owns tenants; your application holds a projection keyed by the uuid.

```ruby
def current_tenant
  claim = masks_tenant or return nil

  Tenant.find_or_create_by!(uuid: claim["uuid"]) do |tenant|
    tenant.subdomain = claim["subdomain"]
    tenant.name = claim["name"]
  end
end
```

Key on `uuid`, not `subdomain` — a subdomain is routing and can be renamed.

## What the callback checks

`state` is compared in constant time against the value stashed when the flow began, and the id
token's `nonce` against its own stashed value. Both fail closed. The PKCE verifier is deleted from
the session as it is used, so a replayed callback has nothing to exchange with.
