---
title: Self-hosting
description: Run the masks server in production.
---

masks ships as a container image. Point it at a Postgres, and it migrates itself on boot.

```sh
docker pull ghcr.io/masksrb/masks:latest
```

## What it runs

masks is an OpenID Connect and OAuth 2.0 provider. It authenticates people, issues and verifies
tokens, and publishes each tenant's signing keys. It stores nothing about your application's data.

It runs as one container: Puma in front of Rails, with optional Thruster in front of Puma. It needs
one Postgres server, holding a primary database, a cache, and a job queue, named from
`POSTGRES_DATABASE`. The only local disk it uses is the master key.

Background jobs (mail, retries) run in the web process by default. `MASKS_JOBS_IN_WEB_SERVER=false`
moves them to a second container running `bin/jobs`.

## Image tags

| Tag | Pushed on | Platforms |
| --- | --- | --- |
| `:main` | every push to main | amd64 |
| `:<sha>` | every push to main | amd64 |
| `:<version>`, such as `:0.2.0` | a server release | amd64, arm64 |
| `:latest` | a server release, moved to its version | amd64, arm64 |

Pin a version, and read
[CHANGELOG.md](https://github.com/masksrb/masks/blob/main/server/CHANGELOG.md) before moving to a
new one:

```yaml
image: ghcr.io/masksrb/masks:0.2.0
```

## Example `compose.yml`

```yaml
services:
  masks:
    image: ghcr.io/masksrb/masks:latest
    environment:
      POSTGRES_HOST: postgres
      POSTGRES_USER: masks
      POSTGRES_PASSWORD: ...
      POSTGRES_DATABASE: masks
      MASKS_TENANTS: acme
      MASKS_PUBLIC_ORIGIN_TEMPLATE: https://%{subdomain}.auth.example.com
    volumes:
      - masks-storage:/rails/storage
    depends_on:
      - postgres

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: masks
      POSTGRES_PASSWORD: ...
      POSTGRES_DB: masks
    volumes:
      - postgres:/var/lib/postgresql/data

  caddy:
    image: caddy:2-alpine
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy-data:/data
    depends_on:
      - masks

volumes:
  postgres:
  masks-storage:
  caddy-data:
```

```
*.auth.example.com {
  reverse_proxy masks:3000
}
```

| Front | Command | Listens on | Adds |
| --- | --- | --- | --- |
| Puma alone (default) | none needed | `PORT`, `3000` | Nothing. Caddy handles TLS, as above. |
| Thruster | `./bin/thrust ./bin/rails server` | `HTTP_PORT`, `80` | Let's Encrypt TLS with `TLS_DOMAIN`, HTTP/2, asset caching. |

Every variable the server reads is in [ENV vars](/reference/environment/).

## Encryption & secrets

Per tenant, the database holds accounts, sign-in factors, clients, tokens, one RSA signing key, and
an audit trail. Signing keys, second-factor secrets, and connected accounts' tokens are also
encrypted with Rails' Active Record Encryption (AES-256-GCM). Reading them needs the keys as well
as the database.

These four secrets are not in the compose file. They are generated once and never change.

| Secret | Protects |
| --- | --- |
| `SECRET_KEY_BASE` | The session cookie. Anyone holding it can forge one. |
| `ENCRYPTION_PRIMARY_KEY` | The encrypted columns. |
| `ENCRYPTION_DETERMINISTIC_KEY` | Columns looked up by value. Rails requires it. |
| `ENCRYPTION_KEY_DERIVATION_SALT` | The per-column keys derived from the two above. |

On first boot masks derives all four from one master key and writes it to
`/rails/storage/master.key`. Mount that path to a volume, as above. Setting any of the four as an
environment variable overrides it. See [ENV vars](/reference/environment/#required-in-production)
for `MASKS_MASTER_KEY` and `MASKS_MASTER_KEY_FILE`.

:::caution
Keep the master key with your database backups. Losing it makes every encrypted column unreadable,
permanently.
:::

## Multi-tenancy

A tenant is one organization's accounts, clients, and signing key, at its own subdomain. The
compose file above declares Multi tenancy. Swap its `MASKS_TENANTS` line to change mode:

| Mode | In `masks:`'s `environment:` | An unseen hostname |
| --- | --- | --- |
| Single | `MASKS_TENANT: acme` | Served by that one tenant. |
| Multi | `MASKS_TENANTS: acme,demo` | 404. |
| Dynamic | Neither (remove the line) | Claims a new tenant, since the template has `%{subdomain}`. |

See [Declaring tenants](/guides/core-concepts/#declaring-tenants) for how each mode works.
`MASKS_SETUP_TOKEN` sets one setup token for every tenant. See
[Setting a tenant up](/guides/core-concepts/#setting-a-tenant-up).

## System requirements

masks is a small Rails app with no fixed CPU or memory floor. Two variables size it:

| Variable | Default | Sizes |
| --- | --- | --- |
| `RAILS_MAX_THREADS` | `3` | Puma's threads and the database connection pool. |
| `JOB_CONCURRENCY` | `1` | The job supervisor's worker processes. |

Raise either if requests or jobs queue. See [Processes](/reference/environment/#processes).
