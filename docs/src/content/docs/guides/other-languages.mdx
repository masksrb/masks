title: Other languages

masks is a standard OpenID Connect provider, so an app in any language signs people in with its
usual library, using the authorization code flow with PKCE. Everything past that has a masks SDK: a
service or a machine that signs in as itself, a call to an API with a DPoP-bound token, the device
flow, redeeming an initial access token, and an API that checks the tokens it receives.

| Language | Signing people in | The masks SDK |
| --- | --- | --- |
| Browser | [`@masks/client`](#in-the-browser) | `npm install @masks/client` |
| Node and Next.js | [openid-client](#node) or [Auth.js](#nextjs) | `npm install @masks/server` |
| Python | [Authlib](#python) | `masks-client`, from its [release tag](#python) |
| Go | [go-oidc and x/oauth2](#go) | `go get github.com/masksrb/masks/go` |
| Ruby | [`Masks::Rails`](/guides/rails/) | the `masks` gem |

[Connecting via SDK](/guides/connecting-via-sdk/#choosing-an-sdk) compares what each SDK covers.

## Registering the app

In `/manage`, under **Clients → Add client**, choose **Signs actors in**, name the app, and enter its
redirect URI. masks shows the `client_id` and the client secret once. The issuer is the address masks
answers at, such as `https://auth.example.com`, and discovery is at
`/.well-known/openid-configuration` under it. Ask for `groups` as well to receive the
[groups claim](/guides/features/#groups).

A service that signs in as itself is a client that **Signs in as itself**. It holds no redirect URI
and asks for its own token with client credentials.

## In the browser

A single-page app with no backend runs the code flow in the page with
[`@masks/client`](/reference/browser/). It needs a public client, one registered with
`token_endpoint_auth_method` set to `none`, and it keeps its tokens in `sessionStorage`.

```js
import { createBrowserClient } from "@masks/client";

const auth = createBrowserClient({
  issuer: "https://auth.example.com",
  clientId: "spa",
  redirectUri: "https://app.example.com/callback",
  scope: ["openid", "profile"],
  resource: "https://api.example.com",
  dpop: true,
});

if (auth.pending()) {
  const { identity, returnTo } = await auth.callback();
}

await auth.authorize({ returnTo: "/dashboard" });

const response = await auth.fetch("https://api.example.com/files");
```

`fetch` refreshes the access token when it is close to expiring. With `dpop: true`, the page makes a
key it cannot export, binds its tokens to it, and signs a proof for each request.

An app with a backend keeps the tokens there instead, and the page holds only a cookie. The
package's session mode talks to a backend running the `masks` gem's Rails engine.

## Node

With [openid-client](https://github.com/panva/openid-client):

```js
import * as client from "openid-client";

const config = await client.discovery(
  new URL("https://auth.example.com"),
  process.env.MASKS_CLIENT_ID,
  process.env.MASKS_CLIENT_SECRET,
);

app.get("/login", async (req, res) => {
  const verifier = client.randomPKCECodeVerifier();
  req.session.verifier = verifier;

  res.redirect(
    client.buildAuthorizationUrl(config, {
      redirect_uri: "https://app.example.com/callback",
      scope: "openid profile email",
      code_challenge: await client.calculatePKCECodeChallenge(verifier),
      code_challenge_method: "S256",
    }).href,
  );
});

app.get("/callback", async (req, res) => {
  const tokens = await client.authorizationCodeGrant(
    config,
    new URL(req.url, "https://app.example.com"),
    {
      pkceCodeVerifier: req.session.verifier,
    },
  );

  req.session.account = tokens.claims();
  res.redirect("/");
});
```

### A Node service

[`@masks/server`](https://github.com/masksrb/masks/tree/main/node) signs a server in as itself and
calls an API with the token. It uses only `fetch` and Web Crypto, so it runs on Node 20 and later,
Bun, Deno, and the Next.js edge runtime. One key signs the client's assertions and another holds its
tokens, so a token copied off the server is useless without the key.

```ts
import { Client, Issuer, Key } from "@masks/server";

const issuer = await Issuer.discover("https://auth.example.com");
const client = new Client({ issuer, id: clientId, key, dpop });

const source = client.credentialsSource({
  scope: ["files:read"],
  resource: ["https://files.example.com"],
});
const api = client.fetch(source, ["https://files.example.com"]);

const response = await api("https://files.example.com/files");
```

`Key.generate()` makes each key, and `key.jwks()` is the public half to register. The `fetch` it
returns reuses the token, signs a DPoP proof for every request, and sends the token only to the
origins it is given. A server with no browser uses `client.deviceAuthorization` and
`client.awaitDevice` for the device flow.

## Next.js

With [Auth.js](https://authjs.dev), masks is an OpenID Connect provider. Register
`https://app.example.com/api/auth/callback/masks` as the redirect URI.

```ts
import NextAuth from "next-auth";

export const { handlers, auth, signIn, signOut } = NextAuth({
  providers: [
    {
      id: "masks",
      name: "masks",
      type: "oidc",
      issuer: "https://auth.example.com",
      clientId: process.env.AUTH_MASKS_ID,
      clientSecret: process.env.AUTH_MASKS_SECRET,
    },
  ],
});
```

A route handler checks access tokens, DPoP-bound ones included, with `@masks/server`'s verifier:

```ts
import { hasScope, Issuer, Verifier } from "@masks/server";

const issuer = await Issuer.discover("https://auth.example.com");
const verifier = new Verifier(issuer, "https://files.example.com", {
  publicURL: "https://files.example.com",
});

export async function GET(request: Request) {
  try {
    const claims = await verifier.authenticate(request);

    if (!hasScope(claims, "files:read")) return new Response(null, { status: 403 });

    return Response.json({ files: await filesFor(claims.sub) });
  } catch (error) {
    return verifier.challenge(error);
  }
}
```

A Node `http` server or Express app calls `verifier.authenticateNode(request)` instead.

## Python

With [Authlib](https://docs.authlib.org) in Flask:

```python
from authlib.integrations.flask_client import OAuth

oauth = OAuth(app)
oauth.register(
    "masks",
    server_metadata_url="https://auth.example.com/.well-known/openid-configuration",
    client_id=os.environ["MASKS_CLIENT_ID"],
    client_secret=os.environ["MASKS_CLIENT_SECRET"],
    client_kwargs={"scope": "openid profile email", "code_challenge_method": "S256"},
)

@app.route("/login")
def login():
    return oauth.masks.authorize_redirect(url_for("callback", _external=True))

@app.route("/callback")
def callback():
    token = oauth.masks.authorize_access_token()
    session["account"] = token["userinfo"]
    return redirect("/")
```

### A Python service

[`masks-client`](https://github.com/masksrb/masks/tree/main/python) signs a service or a machine in
as itself, and checks tokens in an API. It is not on PyPI yet, so it installs from its release tag:

```sh
pip install "masks-client @ git+https://github.com/masksrb/masks@python-v0.1.0#subdirectory=python"
```

It imports as `masks` and needs Python 3.10 or later. Every call has a synchronous form and an
`async` one.

```python
import httpx
import masks

issuer = masks.discover("https://auth.example.com")
client = masks.Client(issuer, client_id, key=key, dpop=dpop)

source = client.credentials_source(scope=["files:read"], resource=["https://files.example.com"])
with httpx.Client(auth=client.auth(source, "https://files.example.com")) as api:
    response = api.get("https://files.example.com/files")
```

A FastAPI or other ASGI app checks every request with the middleware, and finds the claims at
`request.state.masks_claims`:

```python
from masks.asgi import Middleware

verifier = masks.AsyncVerifier(issuer, "https://files.example.com", public_url="https://files.example.com")
app.add_middleware(Middleware, verifier=verifier)
```

In Django or Flask, `masks.Verifier.authenticate` takes the request's method, URL, and headers, and
raises `masks.InvalidToken` when the check fails.

## Go

With [go-oidc](https://github.com/coreos/go-oidc) and `golang.org/x/oauth2`:

```go
provider, err := oidc.NewProvider(ctx, "https://auth.example.com")
config := oauth2.Config{
	ClientID:     os.Getenv("MASKS_CLIENT_ID"),
	ClientSecret: os.Getenv("MASKS_CLIENT_SECRET"),
	RedirectURL:  "https://app.example.com/callback",
	Endpoint:     provider.Endpoint(),
	Scopes:       []string{oidc.ScopeOpenID, "profile", "email"},
}
verifier := provider.Verifier(&oidc.Config{ClientID: config.ClientID})
```

On `/login`, keep the state and the PKCE verifier in the session and send the browser on:

```go
pkce := oauth2.GenerateVerifier()
http.Redirect(w, r, config.AuthCodeURL(state, oauth2.S256ChallengeOption(pkce)), http.StatusFound)
```

On `/callback`, exchange the code and check the ID token:

```go
token, err := config.Exchange(ctx, r.URL.Query().Get("code"), oauth2.VerifierOption(pkce))
idToken, err := verifier.Verify(ctx, token.Extra("id_token").(string))
var claims struct {
	Email  string   `json:"email"`
	Groups []string `json:"groups"`
}
err = idToken.Claims(&claims)
```

### A Go service

[`github.com/masksrb/masks/go`](https://github.com/masksrb/masks/tree/main/go) signs a service or a
machine in as itself, and checks tokens in an API. Its releases are `go/vX.Y.Z` tags.

```go
issuer, err := masks.Discover(ctx, "https://auth.example.com")
client := &masks.Client{Issuer: issuer, ID: clientID, Key: key, DPoP: dpop}

source := client.CredentialsSource(masks.TokenRequest{
	Scope:    []string{"files:read"},
	Resource: []string{"https://files.example.com"},
})
api := client.HTTPClient(source, "https://files.example.com")

response, err := api.Get("https://files.example.com/files")
```

An API wraps its handlers in the verifier's middleware, and reads the claims with
`masks.ClaimsFrom(ctx)`:

```go
verifier := masks.NewVerifier(issuer, "https://files.example.com")
verifier.PublicURL = "https://files.example.com"

http.Handle("/files", verifier.Middleware(files))
```

## Checking access tokens in an API

An access token from masks is a JWT of type `at+jwt`, signed with a key published at
`/.well-known/jwks.json`. An API checks its signature, its issuer, and that `aud` names the API. An
app asks for a token for the API by sending `resource=https://api.example.com` when it signs in, and
the token's `scope` holds the granted scopes, separated by spaces.

Each SDK's verifier does all of that, and also checks the proof that comes with a DPoP-bound token:
signed by the token's key, made for this method and URL, made in the last minute, and not seen
before. Set its public URL when a proxy sits in front of the API, since a proof names the address the
client used.

In a language with no SDK, a JWT library checks a plain bearer token. With
[jose](https://github.com/panva/jose):

```js
import { createRemoteJWKSet, jwtVerify } from "jose";

const keys = createRemoteJWKSet(
  new URL("https://auth.example.com/.well-known/jwks.json"),
);

const { payload } = await jwtVerify(token, keys, {
  issuer: "https://auth.example.com",
  audience: "https://api.example.com",
  typ: "at+jwt",
});
```

That check alone accepts a DPoP-bound token without its proof, so an API that receives them uses an
SDK's verifier.
