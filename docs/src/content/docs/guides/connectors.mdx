---
title: Register a connector
description: Dynamic client registration and resource indicators, driven end to end.
---

An AI client adding a custom connector registers with no prior arrangement — nobody creates it in an
admin UI first. RFC 7591 dynamic client registration is what makes that possible.

`server/app/controllers/registrations_controller.rb`, `Client.register!`

## Register

```sh
curl -X POST https://demo.auth.example/register \
  -H 'Content-Type: application/json' \
  -d '{
    "client_name": "Claude",
    "redirect_uris": ["https://claude.ai/api/mcp/auth_callback"],
    "grant_types": ["authorization_code", "refresh_token"],
    "scope": "openid profile email offline_access",
    "token_endpoint_auth_method": "none"
  }'
```

```json
{
  "client_id": "2bb32482-4552-440c-a097-8d6ce5d72e48",
  "client_name": "Claude",
  "token_endpoint_auth_method": "none",
  "registration_access_token": "…",
  "registration_client_uri": "https://demo.auth.example/register/2bb32482-…"
}
```

`token_endpoint_auth_method: "none"` makes it a public client — no secret is issued, and PKCE
becomes mandatory rather than optional. The default is `client_secret_basic`.

Rate limited to `MASKS_REGISTRATION_LIMIT` (10) per 10 minutes, per tenant and address.

### Scopes

Leaving `scope` off gets `Client::DEFAULT_SCOPES`, which is `Scopes::STANDARD` — `openid`,
`profile`, `email` and `offline_access`. A connector that cannot refresh has to send the person back
through sign-in to keep working.

`Client.bounded` refuses any scope in the `masks:` namespace with `ScopesUnavailable`: a reserved
scope may only be granted to a client a person approved through the
[handshake](/guides/handshake).

`MASKS_DYNAMIC_CLIENT_SCOPES`, or a tenant's own `dynamic_client_scopes`, caps what dynamic
registration may ask for at all.

## Manage it afterwards (RFC 7592)

The `registration_access_token` is the only credential that works against
`registration_client_uri`:

```sh
curl -H "Authorization: Bearer $REGISTRATION_TOKEN" \
  https://demo.auth.example/register/$CLIENT_ID
```

`PUT` updates the metadata, `DELETE` archives the client. A wrong token, or the right token against
another tenant, is `401`.

## Redirect URIs

Validated at registration by `redirect_uris_are_usable`, not at authorize time. They must be
absolute, carry no fragment, and use `https` unless the host is loopback (`Client::LOOPBACK`:
`localhost`, `127.0.0.1`, `::1`). So `http://localhost:3000/callback` is accepted and
`http://example.com/callback` is not.

At `/authorize` the comparison is exact string equality against a registered URI. There is no prefix
or wildcard matching.

## Then the normal flow

```
GET /authorize
  ?response_type=code
  &client_id=2bb32482-…
  &redirect_uri=https%3A%2F%2Fclaude.ai%2Fapi%2Fmcp%2Fauth_callback
  &scope=openid+profile+email+offline_access
  &state=…
  &code_challenge=…&code_challenge_method=S256
  &resource=https%3A%2F%2Fdemo.things.example%2Fmcp
```

`resource` is what makes the resulting access token usable at your API and useless anywhere else —
see [tokens and audiences](/concepts/tokens).

Sign-in and consent happen in the browser; the redirect back carries `code`, `state` and `iss`. Then
exchange it:

```sh
curl -X POST https://demo.auth.example/token \
  -d grant_type=authorization_code \
  -d code=… \
  -d client_id=… \
  -d redirect_uri=https://claude.ai/api/mcp/auth_callback \
  -d code_verifier=… \
  -d resource=https://demo.things.example/mcp
```

## From Ruby

```ruby
issuer = Masks::Client.issuer("https://demo.auth.example")

registration = Masks::Client::Registration.create(
  issuer,
  name: "things",
  redirect_uris: ["https://demo.things.example/auth/callback"],
  scope: %w[openid profile email offline_access]
)

session = registration.session(redirect_uri: "https://demo.things.example/auth/callback")
started = session.start(resource: "https://demo.things.example/mcp")

# redirect the browser to started[:url], keep started[:verifier] and started[:state]

tokens = session.complete(code: params[:code], verifier: started[:verifier])
```
