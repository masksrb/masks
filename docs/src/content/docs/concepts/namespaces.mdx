---
title: Namespaces
description: A scope prefix an application claims, so it can publish scopes masks never has to know.
---

An application that needs scopes of its own, such as `things:read` and `things:settings:admin`,
claims the prefix `things:` once. After that, the application publishes any scope beneath the prefix,
and masks does not need to be told about it.

## Claiming

A namespace is claimed when a person approves a handshake that asks for a prefix. That person holds
`masks:manage`, or holds `masks:handshake` and every scope the handshake asks for. The claim records
the name, the resource that holds it, and the time of the claim. masks also grants the prefix to the
person who approved the handshake, so the person who connected the application can use it.

Each name belongs to one resource. When a second application asks for a prefix that another resource
already holds, masks refuses the handshake before it renders the approval screen. The refusal names
the resource that holds the prefix.

## Releasing

A claim remains after its client is archived or deleted. Releasing a namespace frees the name for the
next application to claim.

`/manage` enforces two steps in this order:

1. Archive the client that holds the namespace.
2. Release the namespace.

A namespace whose client is still active cannot be released. `/manage` shows *archive to release*
in place of the **Release** button. After a release, the scopes beneath the name no longer refer to
what they did before. Claim a namespace only for an application that needs its own scopes.
