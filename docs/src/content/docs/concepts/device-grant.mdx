---
title: Device sign-in
description: How a device without a browser, such as a television or a CLI, signs in with a short code.
---

A device that can display a short code but cannot run a browser, such as a television, a CLI, or
an appliance, signs in through the device grant,
[RFC 8628](https://www.rfc-editor.org/rfc/rfc8628). The device requests a code, displays it, and
polls for a token. The person enters the code on another device, such as a phone, and approves the
sign-in there.

The client must be registered for the grant, in the same way it is registered for any other grant:

```json
{ "grant_types": ["urn:ietf:params:oauth:grant-type:device_code"] }
```

## What the device does

1. The device requests a code:

   ```sh
   curl -X POST https://acme.auth.example.com/device_authorization \
     -d client_id=... -d scope="openid profile"
   ```

   ```json
   {
     "device_code": "...",
     "user_code": "BCDF-GHJK",
     "verification_uri": "https://acme.auth.example.com/device",
     "verification_uri_complete": "https://acme.auth.example.com/device?user_code=BCDF-GHJK",
     "expires_in": 900,
     "interval": 5
   }
   ```

2. The device displays the `user_code` and the `verification_uri`. A device that can display a QR
   code can encode `verification_uri_complete` in it, so the person does not have to type the code.

3. The device polls the token endpoint, no more often than every `interval` seconds:

   ```sh
   curl -X POST https://acme.auth.example.com/token \
     -d grant_type=urn:ietf:params:oauth:grant-type:device_code \
     -d device_code=... -d client_id=...
   ```

| answer | what it means |
| --- | --- |
| `authorization_pending` | nobody has entered the code yet. Keep polling. |
| `slow_down` | the device polled within `interval`. Add five seconds to the interval and keep polling. |
| `access_denied` | the person declined. Stop polling. |
| `expired_token` | the code expired after fifteen minutes. Request a new code. |
| a token | the person approved the sign-in |

A device code can be redeemed for one token only. Polling again after the token is issued returns
`invalid_grant`, so a device code that is stolen after use cannot be redeemed.

## What the person does

1. The person opens `/device` and enters the code.
2. They sign in with whatever the tenant requires, such as a password, a passkey, a provider, or a
   second factor.
3. They see the same consent screen that an application shows, naming the device's client and the
   scopes it requested.
4. Approving issues the token to the polling device. Declining returns `access_denied` to the
   device.

## The user code

The code is eight letters drawn from a twenty-letter alphabet with no vowels, so it cannot spell
words, and `O` cannot be confused with `0`. Case and dashes are ignored, so `bcdfghjk` is the same
code as `BCDF-GHJK`. Attempts at `/device` are rate limited per address, because a short code
is secure only while guessing it is slow.
