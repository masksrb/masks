---
title: Delegation
description: Let an application use somebody's Google, Microsoft or MCP account while they are away.
---

A **delegation** lets one application act as one person at a provider while nobody is signed in. For
example, an application can sync a person's Google Drive at 3 a.m., or an agent can call a person's
Notion MCP server.

- masks stores the provider's tokens and refreshes them.
- The application receives an access token for **one** person's account, and only after that person
  consented to **that** application.
- The application calls the provider directly. It returns to masks only when its token expires.

Each person sees every application that uses each of their accounts on their masks account page, and
can stop any of them there.

## 1. Set up the provider

In `/manage`, on the provider's page:

1. Switch on **Let applications use somebody's Google account**. The label names the provider.
2. Fill in **What applications may do** with the provider's own scopes beyond sign-in.
3. Fill in **Extra parameters when connecting** if the provider needs them to return a refresh token.

| provider | what applications may do | extra parameters |
| --- | --- | --- |
| Google | `https://www.googleapis.com/auth/drive.readonly` | `access_type=offline prompt=consent` |
| Microsoft | `offline_access Files.Read.All` | |
| an MCP server | nothing | |

The presets fill in these values. Delegation uses the same redirect URI that you gave the provider
for sign-in.

An MCP server needs only its URL. masks discovers its authorization server and registers itself with
it. See [MCP servers](#mcp-servers).

## 2. Let the application ask

Only an **approved** client can receive a delegation. The client needs the following settings:

| | |
| --- | --- |
| `allowed_scopes` | includes `masks:delegate:` (every provider) or `masks:delegate:google` (one provider) |
| `grant_types` | includes `refresh_token` and `urn:ietf:params:oauth:grant-type:token-exchange` |

A [handshake](/concepts/clients/) that asks for `masks:delegate:` sets both. With the Rails engine:

```ruby
config.delegates = true
config.delegation_redirect_uri = ->(request) { "#{request.base_url}/connect/callback" }
```

## 3. Connect an account

1. Send the person's browser to `/authorize`:

   ```
   GET https://auth.example.com/authorize
     ?response_type=code
     &client_id=CLIENT_ID
     &redirect_uri=https://app.example.com/connect/callback
     &scope=openid offline_access masks:delegate:google
     &state=STATE
     &code_challenge=CHALLENGE
     &code_challenge_method=S256
   ```

   Keep `state` and the PKCE verifier in the person's session.

2. masks signs the person in and asks for their consent. If masks holds no usable token for the
   person, it sends them on to Google. masks then redirects back to the application:

   ```
   GET https://app.example.com/connect/callback?code=CODE&state=STATE
   ```

3. Check that `state` matches, then redeem the code. Authenticate as the registered client, with
   basic auth or with `client_id` and `client_secret` in the body:

   ```
   POST https://auth.example.com/token
   Authorization: Basic base64(CLIENT_ID:CLIENT_SECRET)
   Content-Type: application/x-www-form-urlencoded

   grant_type=authorization_code
   &code=CODE
   &redirect_uri=https://app.example.com/connect/callback
   &code_verifier=VERIFIER
   ```

   ```json
   {
     "access_token": "eyJ…",
     "refresh_token": "Xk2…",
     "delegations": [
       { "connection": "3f1c9a0e-…", "provider": "google", "provider_name": "Google",
         "label": "ada@example.com", "subject": "8f4c…" }
     ]
   }
   ```

4. Store two values, encrypted, with the record that uses the account:

   | | |
   | --- | --- |
   | `delegations[].connection` | identifies the account |
   | `refresh_token` | the secret you exchange for tokens |

`subject` identifies the person who connected the account. It is the same `sub` that your sign-in
receives, so you can refuse a connection that was finished by a different person than the one who
started it.

If the callback returns an error in place of a code:

| `error` | do |
| --- | --- |
| `access_denied` | The person declined, in masks or at the provider, or chose a provider account that belongs to someone else in masks. |
| `login_required` | Send them again with `prompt=login`. Connecting a new account requires a sign-in within the last 15 minutes. |
| `interaction_required` | You sent `prompt=none`, and masks needs to ask the person something. |
| `unauthorized_client` | The client is not approved. |
| `invalid_scope` | No provider with that key lets applications use it. |

## 4. Get a token

When you have no provider token, or the token is about to expire, make two requests.

1. **Refresh** the secret:

   ```
   POST https://auth.example.com/token
   Authorization: Basic base64(CLIENT_ID:CLIENT_SECRET)

   grant_type=refresh_token
   &refresh_token=SECRET
   ```

   ```json
   { "access_token": "eyJ…", "refresh_token": "NEW_SECRET", "expires_in": 3600 }
   ```

   **Save `NEW_SECRET` immediately**, before anything else. The old secret is spent.

2. **Exchange** the masks access token for the provider's access token:

   ```
   POST https://auth.example.com/token
   Authorization: Basic base64(CLIENT_ID:CLIENT_SECRET)

   grant_type=urn:ietf:params:oauth:grant-type:token-exchange
   &subject_token=eyJ…
   &subject_token_type=urn:ietf:params:oauth:token-type:access_token
   &requested_token_type=urn:masks:params:oauth:token-type:upstream_access_token
   &audience=3f1c9a0e-…
   ```

   ```json
   {
     "access_token": "ya29.…",
     "issued_token_type": "urn:masks:params:oauth:token-type:upstream_access_token",
     "token_type": "Bearer",
     "expires_in": 3542,
     "scope": "https://www.googleapis.com/auth/drive.readonly"
   }
   ```

Call Google with `ya29.…` until `expires_in` runs out. If Google returns 401 before then, discard the
token and repeat step 4.

| answer | means | do |
| --- | --- | --- |
| `400 invalid_grant` | The person stopped your application or disconnected the account, or the provider refused. | Stop, and ask the person to connect again. |
| `403 insufficient_scope` | The token lacks `masks:delegate:<provider>`. | You narrowed the scope on refresh. Request the full scope. |
| `503 temporarily_unavailable` | The provider did not respond. | Retry later. Nothing was lost. |

## Rules for the secret

1. **Keep every new secret.** Each refresh replaces the secret, even when the exchange that follows
   fails.
2. **Refresh each secret only once at a time.** When a secret is spent twice, masks revokes the whole
   chain, and the person has to connect again. Lock around step 4 if more than one worker can reach
   it.
3. **Use the secret within 30 days.** An unused secret expires after 30 days. Each refresh restarts
   the 30 days.

## What masks checks

masks releases a provider token only when all of the following are true:

- The client is approved and registered for token exchange.
- The masks token is live, was issued to this client, and includes `masks:delegate:<provider>`.
- The connection is live and belongs to the person the masks token was issued for.
- The provider still lets applications use it.
- The person's delegation to this client for this connection is live.
- The exchange request sends no `scope`, `resource`, or `requested_lifetime`.

masks records every release as a `delegation.released` event.

masks refreshes the provider's token when it is within a minute of expiring. It refreshes one
connection at a time, so concurrent releases for the same connection wait for each other. masks
encrypts the provider's tokens at rest. When a manager changes what a provider lets applications do,
every person has to connect that provider again.

## MCP servers

An MCP server that is its own OAuth server, such as `https://mcp.notion.com/mcp`, is a provider with
the protocol `mcp`. When you give masks the URL, masks:

1. Reads `/.well-known/oauth-protected-resource` to find the authorization server
   ([RFC 9728](https://www.rfc-editor.org/rfc/rfc9728)).
2. Reads that server's metadata. The server has to offer PKCE with S256 and dynamic registration.
3. Registers itself ([RFC 7591](https://www.rfc-editor.org/rfc/rfc7591)), with a client secret
   whenever the server accepts one.

Every request to the server names the server's URL as `resource`
([RFC 8707](https://www.rfc-editor.org/rfc/rfc8707)). An MCP provider never signs anyone in. Your
application follows steps 3 and 4 as described above, and sends the token it receives to the MCP
server as `Authorization: Bearer`.

## From Ruby

```ruby
delegations = Masks::Client.delegations(issuer, client_id:, client_secret:, redirect_uri:)

started = delegations.start(provider: "google")
session[:connecting] = started
redirect_to started["url"]

held = delegations.finish(params: params, started: session.delete(:connecting))
save(held.connection, held.secret)

upstream = delegations.token(secret, connection: connection)
save(connection, upstream.secret)
upstream.access_token
```

`token` performs step 4. It raises `Delegations::Refused` when the person has to connect again, and
`Delegations::Unavailable` when the application should retry later. Both errors include `secret` when
the refresh has already rotated it, so save that secret as well. Tests use
`Masks::Client::Delegations::Fake`, which needs no issuer.
