A session lasts fourteen days and dies. A device is the browser behind it, and it outlives every
session it ever held.

`server/app/models/device.rb`, `server/app/models/device_factor.rb`

```
devices          public_id  version  name  user_agent  ip_address  last_seen_at  blocked_at
sessions         device_id  device_version
tokens           device_id
device_factors   device_id  actor_id  factor  satisfied_at  expires_at
```

| Constant | |
| --- | --- |
| `Device::COOKIE` | `masks_device` |
| `Device::LIFETIME` | 400 days |
| `Device::IDLE` | 5 minutes between `last_seen_at` writes |
| `DeviceFactor::LIFETIME` | 30 days |

## Where the identity lives

`public_id` is `SecureRandom.urlsafe_base64(24)`, held in a signed, `httponly` cookie with a
400-day sliding expiry. It is not the session cookie and does not travel with it: signing out
clears `masks_session` and leaves the device alone, so the next sign-in from that browser lands on
the same row.

A device is minted on the first `POST /login`, never on a `GET`. Anonymous traffic, crawlers and the
machine endpoints (`/token`, `/introspect`, `/userinfo`) send no device cookie and create no rows.

## Version is the revocation primitive

Every session records the `device_version` it started under. `Session.resume` returns nothing unless
the device still carries it.

```ruby
def bound?
  device.nil? || device.carries?(self)
end
```

`rotate!` is one `UPDATE` of one column, and invalidates every session on that device at once
without walking them. `sign_out!` rotates, revokes the sessions and tokens the device holds, and
drops what it was trusted for:

```ruby
def sign_out!
  transaction do
    rotate!
    sessions.live.find_each(&:revoke!)
    tokens.live.find_each(&:revoke!)
    device_factors.delete_all
  end
end
```

Tokens inherit the device from their parent, so an authorization code issued to a browser passes it
to the access and refresh tokens minted from it. Signing a device out therefore stops the
applications it authorized as well as the browser.

## Blocking

`blocked_at` is checked twice: in `ApplicationController`, which answers `403` to any request
carrying a blocked device's cookie, and in `carries?`, so a blocked device resumes nothing even if
the cookie survives. `block!` signs the device out in the same transaction.

Blocking your own device locks you out of `/manage` from that browser, which is what the control is
for.

## What a device is called

The label comes from `DeviceDetector`, falling back to `Unknown device`, until somebody names it:

```ruby
def label
  name.presence || detected_label
end
```

An unreadable user agent is recorded rather than rejected. `known?` reports the difference and
gates nothing. Neither does the IP: a mismatch between the address a device was last seen at and
the one it arrives from is normal on mobile and behind a VPN, so masks tracks it and never enforces
it.

## Trusting a device with a factor

`device_factors` is the durable half of the login machine's factor stamps. Ticking **do not ask for
a code on this device** on the second-factor prompt writes one row with a 30-day expiry, and
`Login#second_factored?` consults it:

```ruby
def second_factored?
  return false if reauthenticating? || stale?

  touched?(:second_factor) || signed_in? || remembered?(:second_factor)
end
```

Only the second factor is ever remembered. The first is asked for every time, so a stolen device
cookie is worth nothing without the password or the passkey.

A remembered device notes `mfa` in `amr` and not `otp`: multi-factor authentication is what this
browser proved, and a code is not what was entered this time. `max_age` and `prompt=login` are
untouched by any of it — `reauthenticating?` and `stale?` short-circuit ahead of the remembered
row.

Every remembered factor for an actor is dropped when their password changes, when an admin disables
their authenticator, and when the device is signed out.

## Who sees what

A person sees their own devices on `/account` — label, address, when each was last seen, which one
they are on, and which ones skip their code — and can rename or sign out any of them.

An admin sees every device in the tenant under `/manage`, with the actors that signed in from each,
and can sign one out, block it, or release it.

```graphql
{ devices(blocked: false) { id label category known ipAddress lastSeenAt actors { nickname } } }

mutation { blockDevice(id: "12") { device { blockedAt } } }
```
