An actor is an account. It has a nickname, an email address, or both, and a list of scopes. A token
issued for the actor contains only scopes from that list.

| Field | |
| --- | --- |
| `nickname` | Typed at sign-in. It can be renamed without creating a new account. |
| `email` / `email_verified_at` | Changing the address clears its verification. |
| `scopes` | The upper limit on the scopes of any token for this actor. |
| `activated_at` | Unset while an invitation is outstanding. |

## What names an account

One tenant setting, `named_by`, controls which of the two fields every account must have. A manager
sets it in `/manage`. `MASKS_NAMED_BY` pins it at deploy time. A pinned value takes precedence over
the stored one, and changing it requires changing the deployment.

| `MASKS_NAMED_BY` | |
| --- | --- |
| `nickname` | Every account needs a nickname. An address is optional. |
| `email` | Every account needs an address. A nickname is optional. |
| `either` | Either one is enough. This is the default. |

Under every setting, an account must have at least one of the two fields. Both the model and a
database constraint enforce this. **An actor holding `masks:manage` needs both.** masks sends
invitations, password resets, and address confirmations to managers, so a manager must have a
place to receive them. masks refuses to grant `masks:manage` to an account that has
only one of the two until the other is filled in.

An actor signs in with either field. `Actor.locate` accepts a nickname or an address, and the
sign-in screen accepts whichever one the person has. `identifier` returns the nickname when one is
set and the address otherwise. `/manage`, the activity list, and the introspection endpoint display
`identifier`.

Second factors are a TOTP authenticator, passkeys, and backup codes. A passkey can serve as both
the first and the second factor.

Three methods determine which scopes an actor may have:

- `holds?(scope)` returns whether this exact scope is in the actor's list.
- `withheld(scopes)` returns the scopes from the argument that the actor cannot be granted.
- `grant!(scopes)` adds scopes to the actor's list. Claiming a [namespace](/concepts/namespaces/)
  calls it.

## The first actor

The first-run screen creates the first actor on a tenant, and that actor holds `masks:manage`. The
screen has three tabs:

1. **Identification** asks for the manager's nickname, address, and optional name.
2. **Credentials** asks for a password, entered twice.
3. **Configuration** asks for the name of this installation.

The screen does not appear again once the tenant has an actor. After that, managers invite or create
accounts from `/manage`, which also edits every other tenant setting.
