---
title: Signing keys
description: Each tenant has its own RSA keypair, and a rotated key keeps verifying for 24 hours.
---

Every tenant generates its own RSA keypair when it is created. The private key is encrypted at
rest. The public key is published as a JWK at that tenant's JWKS endpoint, and as a self-signed
certificate in the tenant's [SAML metadata](/concepts/saml-applications/).

Because each tenant has its own keys, a token minted for one tenant fails verification at every
other tenant. The token's `kid` is not listed in the other tenant's JWKS, so verification refuses
the token.

## States

| State | |
| --- | --- |
| `staged` | published at JWKS, signing nothing yet |
| `active` | signing every new token |
| `retiring` | no longer signing, still verifying |
| `retired` | removed from JWKS |

## Rotating

A key is staged before it is activated so that clients that cache JWKS fetch the new key *before*
any token is signed with it. Activation then does not depend on when each client refreshes its
cache.

- **Stage** publishes a new key ahead of time. Only one key may be staged at a time. A staged key
  can be discarded, because nothing has been signed with it.
- **Activate** makes a staged key the signing key. The outgoing key keeps verifying for 24 hours.
- **Rotate** generates a new key and activates it immediately, for when there is no time to wait
  for caches. The outgoing key keeps verifying for 24 hours.

Only a staged key can be activated or discarded. A key that is signing, retiring, or retired
cannot be activated again, and it cannot be discarded.
