---
title: Policies
description: Declarative checks named after what they assert, and the redirectable flag that decides where a denial goes.
---

A policy is a list of named checks run against a subject. Reading the list tells you what a request
has to satisfy without reading a method body.

`server/app/policies/`

```ruby
class AuthorizationPolicy < Policy
  uses ClientPolicy
  checks :response_type_is_supported,
         :client_may_use_the_code_grant,
         :pkce_is_present_when_required,
         :challenge_method_is_supported,
         :scopes_are_permitted,
         :resources_are_absolute
end
```

| | |
| --- | --- |
| `uses` | run another policy first, in full |
| `checks` | methods on this policy, in declaration order |
| `delegate … to: :subject` | what the checks read |

Both `uses` and `checks` inherit, and both are de-duplicated before running.
`ClientPolicy` runs ahead of `AuthorizationPolicy` because scopes cannot be checked against a client
that has not been established to exist.

The three that ship:

| | Checks |
| --- | --- |
| `ClientPolicy` | `client_is_known`, `redirect_uri_is_registered` |
| `AuthorizationPolicy` | the six above, plus `ClientPolicy`'s |
| `ExchangePolicy` | `client_may_exchange`, `token_types_are_supported`, `subject_token_is_live`, `scopes_only_narrow`, `audience_only_narrows`, `lifetime_only_shortens` |

Run one with `ClientPolicy.new(authorization).call`.

## Denials carry four things

```ruby
def pkce_is_present_when_required
  if client.public? && code_challenge.blank?
    deny!("invalid_request",
          "a public client must send code_challenge",
          redirectable: true)
  end
end
```

`Policy::Denied` holds an OAuth `error` code, a `description`, an HTTP `status` (default
`:bad_request`), and `redirectable`.

`redirectable` is the load-bearing one. `invalid_client` and an unregistered `redirect_uri` are not
redirectable — if they were, an attacker could point `redirect_uri` anywhere and use the error
response as an open redirector. Everything checked *after* the client and its redirect URI are
established is redirectable, because by then the destination is one the client registered.

```ruby
rescue Policy::Denied => denial
  if denial.redirectable && authorization.client&.redirect_uri?(authorization.redirect_uri)
    redirect_to authorization.redirect_with(issuer:, error: denial.error, …)
  else
    render :error, status: denial.status
  end
```

The non-redirectable branch renders a page rather than a JSON body, because a refusal with nowhere
safe to send it is one a person is looking at. A client that asks for JSON still gets `to_h`.

## Writing one

Subclass `Policy`, delegate what you need from the subject, keep each check to one assertion, and
name the method after what it asserts.

```ruby
class ClientPolicy < Policy
  checks :client_is_known, :redirect_uri_is_registered

  delegate :client, :redirect_uri, to: :subject

  private

    def client_is_known
      deny!("invalid_client", "no client is registered with that client_id") if client.nil?
    end

    def redirect_uri_is_registered
      if redirect_uri.blank?
        deny!("invalid_request", "redirect_uri is required")
      elsif !client.redirect_uri?(redirect_uri)
        deny!("invalid_request", "redirect_uri is not registered for this client")
      end
    end
end
```
