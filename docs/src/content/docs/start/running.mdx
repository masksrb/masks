---
title: Running it
description: Postgres in Docker, Rails on the host, two tenants with their own signing keys.
---

```sh
bin/setup
bin/dev
```

`bin/setup` refuses first if `pg_dump` 17 is not on your `PATH` and `PG_BIN_PATH` is unset — the
schema is dumped as SQL, and an older `pg_dump` will not read a newer server. Then it copies
`server/.env.example` to `.env`, brings Postgres up, installs dependencies, runs `db:prepare`, and
runs `bin/rails masks:tenants`.

Postgres runs in Docker; Rails runs on the host. The application connects as a **non-superuser** role
created by `db/docker-entrypoint-initdb.d`, because a superuser bypasses row-level security
unconditionally and `POSTGRES_USER` is created as one.

## Two tenants

`MASKS_TENANTS` in `.env` declares `demo,acme`. Each gets its own RS256 signing key on create.

Tenants are addressed by subdomain. Either add them to your hosts file:

```
127.0.0.1 auth.test demo.auth.test acme.auth.test
```

...or use `*.auth.localhost`, which resolves without any setup. Then
[demo.auth.localhost:5555](http://demo.auth.localhost:5555).

First run asks you to **set it up**: a tenant with no actors puts `LoginStates::Setup` at the head of
the login machine, and the nickname and password you type there create the owner. There is no seeded
account and no password written down anywhere.

Two declared tenants mean there is always a second one for a forgotten scope to show up against.
The fastest end-to-end check is the keys:

```sh
curl -H "Host: demo.auth.test" localhost:5555/.well-known/jwks.json
curl -H "Host: acme.auth.test" localhost:5555/.well-known/jwks.json
```

Different `kid` values, and neither JWKS can verify the other's tokens. See
[Signing keys](/concepts/keys).

## Configuration

Everything that names a host, a port, or a credential arrives through the environment;
`server/.env.example` documents the full set. [Configuration](/reference/configuration) lists every
variable.

| | |
| --- | --- |
| `POSTGRES_*` | where the database is; port 5435 in development |
| `ENCRYPTION_*` | ActiveRecord encryption keys — replace before storing anything real |
| `MASKS_TENANTS` | comma or space separated, ensured on boot |
| `MASKS_TENANT` | one tenant, reached at every hostname — see [Tenancy](/concepts/tenancy) |
| `MASKS_HOST_SUFFIX` | the suffix tenant subdomains hang off in development |
| `MASKS_PUBLIC_ORIGIN_TEMPLATE` | the origin this installation is reached at; takes `%{subdomain}` |

`MASKS_PUBLIC_ORIGIN_TEMPLATE` may be left blank in development, where the origin falls back to the
host the request arrived on. Everywhere else the application refuses to boot without it, because
that fallback means the issuer and every emailed link follow the `Host` header. A single-tenant
deployment wants a literal origin with no `%{subdomain}` in it.
