```
server/    the standalone OIDC provider     you run one
client/    masks                            any ruby app that talks to it, Rails or not
web/       @masks/client                    a single-page app, in either of two modes
```

## Which do I need?

| I want to… | Use |
| --- | --- |
| run an auth server | `server/` |
| sign a Rails app in | `masks` — the engine mounts itself |
| verify tokens in an API | `masks` |
| drive the flow by hand, or in a non-Rails app | `masks` |
| sign in an SPA in front of a Rails app | `masks` + [`@masks/client`](/guides/spa) in BFF mode |
| sign in an SPA with no backend of its own | [`@masks/client`](/guides/spa) in browser PKCE mode |

A resource server — something that only *receives* bearer tokens and never signs anyone in — needs
`masks` and nothing else. See [verifying a token](/guides/verifying).

## The server

Rails 8, `config.load_defaults 8.1`, no Active Storage, no Action Cable, no Action Text. It owns its
routes, its session and its cookie; there is no host application. See
[Endpoints](/reference/endpoints).

## The gem

One gem, version `0.6.0` (`client/lib/masks/version.rb`), holding both halves of the consumer side.

`require "masks"` loads `Masks::Client` always, and `Masks::Rails` only when `::Rails::Engine` is
already defined, so a Rack or Sinatra service takes on `jwt` and no framework.

| | |
| --- | --- |
| `Masks::Client.issuer(url)` | discovery and JWKS, cached |
| `Masks::Client.verifier(url, audience:)` | for a resource server |
| `Masks::Client.resource(url, issuer:)` | protected-resource metadata |
| `Masks::Client.handshake(url, **)` | the approval flow |
| `Masks::Client::Session` | the code flow, end to end |
| `Masks::Client::Registration` | RFC 7591 / 7592 |

Full API: [Masks::Client](/libraries/ruby).

The engine mounts nine routes into your application and gives you `authenticate_masks!`. It issues
nothing and holds no signing key, and talks to the server over HTTP like any other client. Full API:
[Masks::Rails](/libraries/rails).

The two halves are never loaded into the same process.

## The browser package

`@masks/client`, in `web/`, version `2.1.0`. Two modes: a session against a backend that mounts the
engine, or the authorization code flow run in the page. See [Sign an SPA in](/guides/spa) for the
walkthrough and [@masks/client](/libraries/browser) for the API.

## Multi-tenant hosts

Every configuration value in the engine accepts a callable taking the request, which is how an
application serving many tenants on subdomains resolves its issuer per request:

```ruby
Masks::Rails.configure do |config|
  config.issuer = ->(request) { "https://#{request.host.split(".").first}.auth.example" }
  config.resource = ->(request) { "https://#{request.host}/mcp" }
end
```
