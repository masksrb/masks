---
title: Hono
description: "Sign people in to a Hono app on Node, Bun, Deno, or Cloudflare Workers with the masksHono middleware."
---

`masksHono` from `@masks/server/hono` reads the [options](/reference/javascript/#setting-up) every integration shares.

```ts
import { Hono } from "hono";
import { masksHono, requireAuth } from "@masks/server/hono";

const app = new Hono();

app.use(masksHono({ name: "Catalog", privileges: { admin: ["catalog:admin"] } }));
app.get("/", (c) => c.json(c.get("masked")));
app.get("/settings", requireAuth("admin"), (c) => c.json({ subject: c.get("masked").subject }));
```

`c.get("masked")` is typed in any Hono app. `requireAuth` needs `masksHono` to run first. A refusal
is thrown as an `HTTPException` that carries the masks answer, so Hono sends that answer unless
`app.onError` changes it.

On Cloudflare Workers, `masksHono` reads `MASKS_ISSUER`, `MASKS_RESOURCE`, and `MASKS_SECRET` from
the Worker's variables and secrets. A Worker has no file to write the handshake's credentials to, so
set `MASKS_CLIENT_ID` and `MASKS_CLIENT_SECRET` as secrets, or pass a `credentials` store of your own.
See [the handshake](/reference/javascript/#the-handshake).
