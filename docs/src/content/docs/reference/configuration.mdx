## Server

Nothing in the repository names a host, a domain, or a secret. Everything arrives through the
environment; `server/.env.example` documents the set and `bin/setup` copies it to `.env`.
Read in `server/config/application.rb` into `config.masks`.

| | Default | |
| --- | --- | --- |
| `POSTGRES_HOST` `POSTGRES_PORT` | `127.0.0.1`, 5435 | where the database is |
| `POSTGRES_USER` `POSTGRES_PASSWORD` | `masks` | must not be a superuser — RLS is bypassed by one |
| `POSTGRES_DATABASE` | | production only |
| `SECRET_KEY_BASE` | | required in production |
| `ENCRYPTION_PRIMARY_KEY` | | ActiveRecord encryption |
| `ENCRYPTION_DETERMINISTIC_KEY` | | |
| `ENCRYPTION_KEY_DERIVATION_SALT` | | |
| `MASKS_HOST_SUFFIX` | `auth.test` | the suffix tenant subdomains hang off, development only |
| `MASKS_PUBLIC_ORIGIN_TEMPLATE` | *blank* | the origin this installation is reached at; takes `%{subdomain}`. **Required outside development** |
| `PORT` | 5555 | |

Generate real encryption keys with `bin/rails db:encryption:init`. The values in `.env.example` are
development values and are named as such.

### Tenants and first run

| | Default | |
| --- | --- | --- |
| `MASKS_TENANT` | *unset* | one tenant, reached at every hostname |
| `MASKS_TENANTS` | `demo,acme` | comma or space separated; ensured on boot |
| `MASKS_SETUP_TOKEN` | *unset* | required to answer the setup prompt, when set |
| `MASKS_DYNAMIC_CLIENT_SCOPES` | *unset* | caps what dynamic registration may ask for |

Declaring `MASKS_TENANTS` turns claiming off. Leave it unset and the first request to a hostname
nothing serves claims that subdomain — once, and only while no tenant exists at all.

`MASKS_TENANT` is the single-tenant form and names the record rather than a route — see
[Tenancy](/concepts/tenancy). Setting both is refused rather than resolved by precedence, and the
refusal surfaces at boot, from the `masks:tenants` the entrypoint runs.

`MASKS_DYNAMIC_CLIENT_SCOPES` is the installation-wide ceiling; a tenant's own
`dynamic_client_scopes` column overrides it. See [Register a connector](/guides/connectors).

### Accounts and mail

| | Default | |
| --- | --- | --- |
| `MASKS_MAIL_FROM` | *unset* | the address invitations are sent from; unset means no mail is sent |
| `MASKS_INVITATION_LIFETIME` | `604800` — seven days | seconds an invitation stays open |
| `MASKS_PASSWORD_RESET_LIFETIME` | `1800` — thirty minutes | seconds a reset link stays open |
| `MASKS_EMAIL_VERIFICATION_LIFETIME` | `172800` — two days | seconds a confirmation link stays open |

Only the first run creates an account without an invitation. Every account after it is invited by
somebody holding `masks:manage`, and the invitation carries the password nobody has set yet.

`MASKS_MAIL_FROM` decides which of two things happens. With it set, the link is mailed to the
address and is never returned to the administrator — so accepting proves control of the mailbox, and
the address is marked verified. With it unset there is no mail, so the administrator gets the link
to deliver by hand and the address stays unverified.

`email_verified` reports verification and nothing else. An address is confirmed when somebody opens
a link sent to it, and by no other route — not by an administrator setting it, and not by being the
owner. Relying parties that require a verified address will refuse those accounts.

Delivery is ordinary Action Mailer — set `config.action_mailer.smtp_settings` in
`config/environments/production.rb`.

### Rate limits

Each is a count per tenant. [Hardening](/concepts/hardening) has the full table with windows.

| | Default | |
| --- | --- | --- |
| `MASKS_ATTEMPT_LIMIT` | 10 | sign-in and second factor, per address, in 3 minutes |
| `MASKS_ACCOUNT_ATTEMPT_LIMIT` | 5 | sign-in per identifier, and password change, in 3 minutes |
| `MASKS_REGISTRATION_LIMIT` | 10 | dynamic client registration, in 10 minutes |
| `MASKS_RECOVERY_LIMIT` | 5 | forgotten-password and verification requests, in 15 minutes |

### Development only

| | |
| --- | --- |
| `PG_BIN_PATH` | prepended to `PATH`, when the linked `pg_dump` is older than the server |

The schema is dumped as SQL because `schema.rb` cannot represent a row-level security policy — so
`pg_dump` has to match the server it dumps, and refuses outright when it does not. `bin/setup`
checks for one before it does anything else.

`MASKS_PUBLIC_ORIGIN_TEMPLATE` is what the server believes it is reached at. It must be stable,
because OAuth redirect URIs and token audiences are registered against it.

**The application refuses to boot without it outside development**, and `config.hosts` in production
is derived from it. Without it the origin falls back to `request.base_url` — so the issuer, the
registration endpoint and every emailed link follow the `Host` header, and anyone who can reach the
server can have a password reset delivered to a host they control. `/up` is excluded from host
authorization so a health check does not have to know the public name.

`%{subdomain}` is optional. A template with no interpolation in it is a literal origin, which is what
a single-tenant deployment wants: with `MASKS_TENANT` set every hostname resolves, so without a
literal here the issuer is whichever hostname the request happened to arrive on.

## The gem

One gem, `masks` (currently 0.5.0), holds both halves of the consumer side. `require "masks"` loads
`Masks::Client` always and `Masks::Rails` only when Rails is already defined.

### Rails

The generator writes this file. Everything has a default except `issuer`.

```ruby
Masks::Rails.configure do |config|
  config.issuer = "https://demo.auth.example"
  config.credentials = -> { { client_id: ENV["MASKS_CLIENT_ID"], client_secret: ENV["MASKS_CLIENT_SECRET"] } }
  config.store = ->(request, registration) { Credentials.store!(registration) }
  config.name = "things"
  config.resource = nil
  config.resource_scopes = []
  config.scope = %w[openid profile email]
end
```

**Connecting**

| | Default | |
| --- | --- | --- |
| `issuer` | | required — the masks issuer this app signs in against |
| `name` | the application's module name | what the approval screen calls this app |
| `credentials` | | `client_id` and `client_secret`, or `nil` when unconnected |
| `store` | | given `(request, registration)` after a [handshake](/guides/handshake) |
| `forget` | | given `(request)` to drop them again; an app that sets `store` and not this is never offered a disconnect |
| `credentials_path` | `config/masks.json` | where the default store writes, when you set neither |

**Asking**

| | Default | |
| --- | --- | --- |
| `scope` | `openid profile email` | what to request, and what the handshake asks to be approved for |
| `resource` | `nil` | the API the access token is for — sets its `aud` |
| `resource_scopes` | `[]` | scope to description, published as RFC 9728 metadata |
| `redirect_uri` | this host's `/auth/callback` | must match a URI the client was approved for |

**Behaviour**

| | Default | |
| --- | --- | --- |
| `after_sign_in` | `/` | where to land, unless a return path was remembered |
| `after_sign_out` | `/` | |
| `sign_out_of_issuer` | `false` | make every sign-out an RP-initiated logout at the issuer |
| `session_key` | `masks` | the session key tokens are stored under |
| `parent_controller` | `ActionController::Base` | what the engine's own pages inherit, for your layout |
| `authenticate_everything` | `false` | include `Authentication` in every controller rather than where you say |

Omit the secret for a public client. An app with no credentials yet is not misconfigured — it is
unconnected, and every refusal says `handshake_required`.

Every one of these accepts a callable taking the request, which is how one application serves many
tenants:

```ruby
config.issuer = ->(request) { "https://#{request.host.split(".").first}.auth.example" }
config.resource = ->(request) { "https://#{request.host}/mcp" }
```

`Configuration#issuer_speaks!` refuses an issuer whose `masks_protocol_version` is below
`MINIMUM_ISSUER`.

### Any Ruby app

No global configuration. Construct what you need:

```ruby
Masks::Client.issuer(url)                        # discovery and JWKS, cached 300s
Masks::Client.verifier(url, audience:)           # for a resource server
Masks::Client.resource(url, issuer:)             # RFC 9728 metadata
Masks::Client.handshake(url, **metadata)
Masks::Client::Session.new(issuer:, client_id:, redirect_uri:, client_secret:, scope:)
Masks::Client::Registration.create(issuer, token: nil, **metadata)
```

`Session` carries `start`, `complete`, `refresh`, `exchange`, `revoke`, `introspect`, `userinfo`,
`identity`, `profile` and `end_session_url`.

A `Registration` carries `client_id`, `client_secret`, `access_token` and `uri`, reads itself back
with `read`, changes itself with `update`, archives itself with `delete`, and builds a `Session`
with `session(redirect_uri:)`.
