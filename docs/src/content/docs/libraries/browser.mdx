description: The browser API — a session against a backend, or the authorization code flow run in the page.
---

`@masks/client`, in `web/`. Version `2.1.0`.

```sh
npm install @masks/client
```

ESM only, no dependencies, side-effect free. Two clients, for the two places a token can live.

| | Use when | Token lives in |
| --- | --- | --- |
| `createSession` | there is a backend mounting the Rails engine | the backend's encrypted session |
| `createBrowserClient` | the page has no backend of its own | memory, with PKCE state in `sessionStorage` |

## Exports

```ts
import {
  createSession,
  createBrowserClient,
  verifyIdToken,
  MasksError,
} from "@masks/client";

import type {
  Account, Avatars, AvatarStyle, Claims, Discovery,
  Refusal, Status, Tenant, Tokens,
  SessionClient, SessionOptions,
  BrowserClient, BrowserOptions,
  Jwk,
} from "@masks/client";
```

## createSession

Speaks to the routes the Rails engine mounts. No token reaches the page.

```ts
const auth = createSession({ basePath: "/auth" });

const status = await auth.status();
```

### SessionOptions

| | Default | |
| --- | --- | --- |
| `basePath` | `/auth` | where the engine is mounted; a trailing slash is trimmed |
| `fetch` | `globalThis.fetch` | |
| `csrfToken` | reads `meta[name="csrf-token"]` | used on logout |

### Methods

| | Returns | |
| --- | --- | --- |
| `status()` | `Promise<Status>` | the three-state answer below |
| `session()` | `Promise<Account \| null>` | the account, or `null` when not signed in |
| `require(options?)` | `Promise<Account>` | the account, or navigates away and never resolves |
| `login(options?)` | `void` | navigate to sign-in |
| `loginUrl(options?)` | `string` | |
| `handshake()` | `void` | navigate to the connect screen |
| `handshakeUrl()` | `string` | |
| `avatarUrl(account, options?)` | `string \| null` | |
| `logout(options?)` | `Promise<void>` | |

`options` on `login`, `loginUrl` and `require` is `{ returnTo?: string }`, defaulting to the current
path and query.

### Status

```ts
type Status =
  | { state: "signed_in"; account: Account }
  | { state: "signed_out"; loginUrl: string }
  | { state: "handshake_required"; handshakeUrl: string };
```

The third state exists because an app nobody has connected must not offer a sign-in button that
leads to an error at the issuer.

```ts
const status = await auth.status();

switch (status.state) {
  case "signed_in":
    show(status.account);
    break;
  case "handshake_required":
    location.assign(status.handshakeUrl);
    break;
  case "signed_out":
    location.assign(status.loginUrl);
}
```

`GET /auth/session` answering anything but `200` or `401` throws `MasksError("session_failed")`
carrying the status.

### avatarUrl

```ts
img.src = auth.avatarUrl(account, { size: 64 });
```

Returns `null` when the account carries no avatars, and when `photo` is asked for and the actor has
uploaded none. `style` defaults to `photo` if there is one, else `identicon`.

A photo returns the local proxy path (`/auth/avatar`), so the token stays on the backend. A
generated style returns the issuer's own URL. `size` is appended as a query parameter.

### logout

```ts
await auth.logout();                        // this app
await auth.logout({ everywhere: true });    // and the issuer
```

`DELETE`s the logout route with the CSRF token. With `everywhere`, the response's `logout_url` is
navigated to and the promise never resolves.

## createBrowserClient

The authorization code flow with PKCE, run in the page. The client is public: no secret, and
`code_challenge` is always sent.

```ts
const auth = createBrowserClient({
  issuer: "https://demo.auth.example",
  clientId: "…",
  redirectUri: "https://app.example.com/callback",
  resource: "https://app.example.com/mcp",
});
```

### BrowserOptions

| | Default | |
| --- | --- | --- |
| `issuer` | — | trailing slash trimmed |
| `clientId` | — | |
| `redirectUri` | — | |
| `scope` | `openid profile email` | a string or an array |
| `resource` | — | a string or an array; repeats as `resource` |
| `fetch` | `globalThis.fetch` | |
| `storage` | `sessionStorage` | holds the PKCE state under `masks:pending` |

### Methods

| | Returns |
| --- | --- |
| `discover()` | `Promise<Discovery>`, cached |
| `authorizeUrl(options?)` | `Promise<string>` |
| `authorize(options?)` | `Promise<void>`, navigates |
| `pending()` | `boolean` |
| `callback(url?)` | `Promise<{ tokens, identity, returnTo }>` |
| `identity()` | `Claims \| null` |
| `avatars()` | `Avatars \| null` |
| `avatarUrl(subject, options?)` | `Promise<string>` |
| `photo(subject?)` | `Promise<Blob \| null>` |
| `refresh()` | `Promise<Tokens>` |
| `tokens()` | `Tokens \| null` |
| `accessToken()` | `string \| null` |
| `authorization()` | `string \| null`, `"Bearer …"` |
| `expired(leeway?)` | `boolean`, `leeway` 30 seconds |
| `logout()` | `void`, clears memory and storage |

`options` on `authorize` and `authorizeUrl` is `{ returnTo?: string; prompt?: string }`.

### The flow

```ts
if (auth.pending()) {
  const { identity, returnTo } = await auth.callback();

  history.replaceState(null, "", returnTo);
  show(identity);
} else {
  await auth.authorize();
}
```

`authorizeUrl` generates a verifier, state and nonce, writes them to `storage`, and returns the URL.
The nonce is generated only when `openid` is in scope.

`callback` reads the query, removes the pending entry, and refuses — in order — an `error`
parameter, no pending entry, a `state` that does not match, and a missing `code`. It then exchanges
the code and, when a nonce was sent, verifies the id token. A verification failure discards the
tokens before rethrowing.

`discover()` throws `invalid_issuer` when the document names an issuer other than the one
configured.

### Avatars

```ts
const blob = await auth.photo();

img.src = blob
  ? URL.createObjectURL(blob)
  : await auth.avatarUrl(subject, { style: "identicon" });
```

`photo()` sends the access token and returns `null` when there is no subject, no token, or the
request is refused. `avatarUrl` reads `avatar_endpoint` from discovery and throws `invalid_style`
for a style the issuer does not list. `style` defaults to `identicon`.

`avatars()` reads the `masks:avatars` claim off the verified id token.

## verifyIdToken

```ts
const claims = await verifyIdToken(token, {
  issuer,
  audience: clientId,
  nonce,
  keyFor,
  leeway: 60,
});
```

`createBrowserClient` calls this itself. Exported for a page that obtains an id token another way.

`keyFor` is `(kid: string) => Promise<Jwk>`. Signatures are verified with WebCrypto
(`RSASSA-PKCS1-v1_5`); `RS256`, `RS384` and `RS512` are accepted, and any other `alg` is refused.

Checked, in order: the token has three segments, `alg` is supported, the signature verifies, `iss`
matches, `aud` contains the audience, `exp` has not passed, `iat` is not in the future, and `nonce`
matches. `leeway` defaults to 60 seconds.

## Types

### Account

```ts
interface Account {
  signed_in: boolean;
  subject?: string;
  name?: string;
  nickname?: string;
  email?: string;
  email_verified?: boolean;
  picture?: string;
  avatars?: Avatars;
  tenant?: Tenant;
  scopes: string[];
  expires_at?: number;
}
```

### Tokens

```ts
interface Tokens {
  access_token: string;
  id_token?: string;
  refresh_token?: string;
  token_type: string;
  scope: string;
  expires_in: number;
  obtained_at: number;
}
```

`obtained_at` is seconds since the epoch, recorded when the token endpoint answered, and is what
`expired()` measures against.

### Avatars

```ts
type AvatarStyle = "photo" | "identicon" | "initials";

interface Avatars {
  photo: string | null;
  identicon: string;
  initials: string;
}
```

### Tenant

```ts
interface Tenant {
  uuid?: string;
  subdomain?: string;
  name?: string;
}
```

### Discovery

The OpenID discovery document, plus `avatar_endpoint`, `avatar_styles_supported`,
`avatar_sizes_supported` and `tenant`. Indexed, so any other claim is readable.

### Refusal

What `/auth/session` answers with `401`.

```ts
interface Refusal {
  signed_in: false;
  error: "login_required" | "handshake_required" | string;
  login_url?: string;
  handshake_url?: string;
}
```

## MasksError

```ts
class MasksError extends Error {
  readonly code: string;
  readonly description?: string;
  readonly status?: number;
}
```

Every rejection from either client is one of these. `status` is set when an HTTP response caused it.

| `code` | Thrown by |
| --- | --- |
| `session_failed` | `status()`, on an unexpected response |
| `invalid_issuer` | discovery naming another issuer, an unreachable JWKS, a missing `jwks_uri` or `avatar_endpoint` |
| `invalid_style` | `avatarUrl`, for a style the issuer does not serve |
| `invalid_state` | `callback`, with no pending entry or a mismatched `state` |
| `invalid_request` | `callback`, with no `code` |
| `invalid_token` | an id token that is malformed, wrongly signed, expired, or for another issuer or client |
| `invalid_nonce` | an id token issued for another request |
| `invalid_grant` | `refresh()`, with no refresh token held |
| `http_<status>` | a token endpoint error carrying no `error` of its own |

An OAuth error returned by the issuer keeps its own code — `access_denied`, `invalid_client` and so
on — with `error_description` as the `description`.
