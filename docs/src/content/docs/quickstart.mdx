masks signs people in to your apps. It is an OpenID Connect and OAuth 2.0 provider, which means it
speaks the standard protocols that apps use to sign people in and get tokens.

You can use masks in four ways:

- [Run it with Docker](#run-it-with-docker) as its own server.
- [Add it to a Rails app](#add-it-to-a-rails-app), to sign people in to that app or to run masks
  inside it.
- [Connect client-side](#connect-client-side) from a single-page app in the browser.
- [Try it locally](#try-it-locally) with the full stack from the repository.

Each section below links to its full guide.

## Run it with Docker

masks comes as a container image, a packaged copy of the server that Docker runs. It needs one
Postgres database, and it migrates the database itself each time it starts.

```yaml
services:
  masks:
    image: ghcr.io/masksrb/masks:latest
    environment:
      POSTGRES_HOST: postgres
      POSTGRES_USER: masks
      POSTGRES_PASSWORD: ...
      POSTGRES_DATABASE: masks
      MASKS_MIGRATION_USER: masks_owner
      MASKS_MIGRATION_PASSWORD: ...
      MASKS_TENANT: acme
      MASKS_PUBLIC_ORIGIN_TEMPLATE: https://auth.example.com
    volumes:
      - masks-storage:/rails/storage
    depends_on:
      - postgres

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ...
    volumes:
      - postgres:/var/lib/postgresql/data
      - ./initdb:/docker-entrypoint-initdb.d:ro

volumes:
  postgres:
  masks-storage:
```

`initdb/01-roles.sql` creates two database roles. The first owns the schema. The second serves
requests.

```sql
CREATE ROLE masks_owner WITH LOGIN PASSWORD '...' CREATEDB;
CREATE ROLE masks WITH LOGIN PASSWORD '...';
```

masks migrates as the first role and serves as the second. Postgres keeps tenants apart with
row-level security, a rule on each table that limits which rows a role can see. The role that
answers requests cannot switch that rule off.

To finish setting up:

1. Put a TLS proxy in front of port `3000`. The proxy serves masks over HTTPS.
2. Open the public origin in a browser.
3. Set up the first account with the setup token that masks prints in its logs.

The first account holds `masks:manage` and can open `/manage`.

:::caution
The `masks-storage` volume holds the generated master key. Every encrypted column depends on it.
Back it up with the database.
:::

See [Self-hosting](/guides/self-hosting/) for TLS, image tags, database roles, secrets, and tenants.

## Add it to a Rails app

The `masks` gem signs people in to your app against a masks server that runs somewhere else.

1. Add the gem:

   ```ruby
   gem "masks"
   ```

2. Run the installer:

   ```sh
   bin/rails generate masks:install --resource https://app.example.com
   ```

   `--resource` is a URL on your app's own origin. The handshake registers your app for that URL.

3. Set `MASKS_ISSUER` to your masks server.
4. Start the app.
5. Open `/auth/handshake` to connect the app to masks.
6. Require a signed-in person in any controller:

   ```ruby
   class ApplicationController < ActionController::Base
     include Masks::Rails::Authentication

     masked!
   end
   ```

To run masks inside your app instead, use the `masks-server` gem. It mounts masks as an engine, a
part of your app with its own routes.

```ruby
gem "masks-server"
```

```sh
bin/rails generate masks:server:install --at /auth
```

See [Rails apps](/guides/rails/) for client, server, and engine mode.

## Connect client-side

`@masks/client` signs people in from a single-page app in the browser.

```sh
npm install @masks/client
```

It has two modes.

### Session mode

Session mode talks to a backend that runs `Masks::Rails`. The backend keeps the tokens and gives the
browser a cookie.

```js
import { createSession } from "@masks/client";

const auth = createSession({ basePath: "/auth" });

const account = await auth.session();
if (!account) auth.login({ returnTo: "/dashboard" });
```

### Browser mode

Browser mode is for an app with no backend. It runs the authorization code flow with PKCE in the
page. PKCE is a check that proves the page that asked for a code is the same page that uses it.

Browser mode needs a public client. A public client is one registered with
`token_endpoint_auth_method` set to `none`, because a page in the browser cannot keep a secret.

```js
import { createBrowserClient } from "@masks/client";

const auth = createBrowserClient({
  issuer: "https://auth.example.com",
  clientId: "...",
  redirectUri: "https://app.example.com/callback",
  scope: ["openid", "profile"],
});

if (auth.pending()) await auth.callback();
else await auth.authorize({ returnTo: "/dashboard" });
```

See [Connecting via SDK](/guides/connecting-via-sdk/) for what each SDK covers, and the
[@masks/client reference](/reference/browser/).

## Try it locally

The repository runs a full stack with `./dev`. You need Docker with Compose, and Ruby.

1. Clone the repository and start the stack:

   ```sh
   git clone https://github.com/masksrb/masks.git
   cd masks
   ./dev
   ```

2. Open masks at `http://masks.localhost:12345`.
3. Set up the first account with the setup token `masks-dev`.

This documentation runs at `http://masks.localhost:12346`.

To start over, run `./dev reset`. It deletes the database and brings back the first-run screen.
