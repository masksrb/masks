masks is an OpenID Connect and OAuth 2.0 provider. You can run it as a container, mount it in a
Rails app, or sign people in against it from the browser. Pick the path that fits, and follow its
link for the full guide.

## Run it with Docker

masks ships as a container image that needs one Postgres. It migrates itself on boot.

```yaml
services:
  masks:
    image: ghcr.io/masksrb/masks:latest
    environment:
      POSTGRES_HOST: postgres
      POSTGRES_USER: masks
      POSTGRES_PASSWORD: ...
      POSTGRES_DATABASE: masks
      MASKS_TENANT: acme
      MASKS_PUBLIC_ORIGIN_TEMPLATE: https://auth.example.com
    volumes:
      - masks-storage:/rails/storage
    depends_on:
      - postgres

  postgres:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: masks
      POSTGRES_PASSWORD: ...
      POSTGRES_DB: masks
    volumes:
      - postgres:/var/lib/postgresql/data

volumes:
  postgres:
  masks-storage:
```

Put a TLS proxy in front of port `3000`, open the public origin, and set up the first account with
the setup token masks prints in its logs. The first account holds `masks:manage` and opens the
console at `/manage`.

See [Self-hosting](/guides/self-hosting/) for TLS, image tags, secrets, and tenants.

## Add it to a Rails app

The `masks` gem signs people in to your app against a masks server that runs somewhere else:

```ruby
gem "masks"
```

```sh
bin/rails generate masks:install
```

Set `MASKS_ISSUER` to your masks server, start the app, and open `/auth/handshake` to connect it.
Then require a signed-in person in any controller:

```ruby
class ApplicationController < ActionController::Base
  include Masks::Rails::Authentication

  before_action :authenticate_masks!
end
```

To run masks inside your app instead, the `masks-server` gem mounts it as an engine:

```ruby
gem "masks-server"
```

```sh
bin/rails generate masks:server:install --at /auth
```

See [Rails apps](/guides/rails/) for client, server, and engine mode.

## Connect client-side

`@masks/client` signs people in from a single-page app:

```sh
npm install @masks/client
```

An app with a backend keeps the tokens on the server and gives the browser a cookie. Session mode
talks to that backend, such as one running `Masks::Rails`:

```js
import { createSession } from "@masks/client";

const auth = createSession({ basePath: "/auth" });

const account = await auth.session();
if (!account) auth.login({ returnTo: "/dashboard" });
```

An app with no backend runs the code flow with PKCE in the page. It needs a public client, one
registered with `token_endpoint_auth_method` set to `none`:

```js
import { createBrowserClient } from "@masks/client";

const auth = createBrowserClient({
  issuer: "https://auth.example.com",
  clientId: "...",
  redirectUri: "https://app.example.com/callback",
  scope: ["openid", "profile"],
});

if (auth.pending()) await auth.callback();
else await auth.authorize({ returnTo: "/dashboard" });
```

See [Connecting via SDK](/guides/connecting-via-sdk/) and the
[@masks/client reference](/reference/browser/).

## Try it locally

The repository runs a full stack with `./dev`. It needs Docker with Compose, and Ruby.

```sh
git clone https://github.com/masksrb/masks.git
cd masks
./dev
```

masks answers at `http://masks.localhost:12345`, and this documentation at
`http://masks.localhost:12346`. The dev stack's setup token is `masks-dev`. `./dev reset` deletes
the database and brings back the first-run screen.
