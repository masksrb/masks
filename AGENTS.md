# Agents

## Writing

All prose in this repo follows [docs/STYLE.md](docs/STYLE.md), which is based on
the Ruby on Rails guides. That includes the docs, the READMEs, the locale files
in `engine/config/locales/`, and the descriptions the reference pages are
generated from: the manage API's GraphQL descriptions and the documentation in
`client/` and `web/`.

- Write plain, declarative sentences in the present tense, in American English
  with the Oxford comma.
- Leave out contrast framing ("X, not Y", "rather than"), closing aphorisms,
  fragments for rhythm, em dashes as general punctuation, metaphor, filler,
  and rhetorical questions.
- `manage`, `javascript/client`, `ruby/client`, and `ruby/rails` under
  `reference/` are generated by `./dev reference`. Change the code they read,
  then regenerate. Never edit those pages by hand.
- `reference/environment` is written by hand. `./dev reference` fails when it
  leaves out a variable the code reads, or lists one that nothing reads.
- Use the words in the Words section of `docs/STYLE.md` for the things people see.
- Check every claim against the code before writing it down.
- The repo is public. Leave out real hostnames, addresses, and anything about
  private infrastructure.

## Releases

- A release that needs a step from the operator, such as a new variable or a
  migration that is run by hand, says so in its notes on GitHub with a line that
  starts with `Operator:`. The health panel reads that line.
- Add first, remove later. A release may add tables, columns, indexes, enum
  values, and settings. It removes or renames one of them only in the release
  after the one that stopped reading it. xixo ships masks inside its image, and
  xixo's updater rolls a server back to the build before, which then runs on
  the database the newer build migrated.
- A migration that moves data runs in the release that adds the new place. The
  release after removes the old one.
