Masks is a traditional Ruby on Rails-based application. If you are familiar with
the framework, then you will find the code quite approachable. When deployed,
Masks exposes a web server on port 5000 (by default).

From there, _clients_ can redirect end-users to the masks server's _login
endpoint_. Typically [^1]:

```
GET /login?client_id=...
```

End-users authenticate as a specific _actor_ (using their credentials), and they
are redirected back to the client app with a _token_ granting access.

[^1]:
    Internal clients can use the following short-hand: `/login/:client_id`.
    Otherwise, these redirects are structured according to the OAuth2/OpenID specs,
    complete with a `redirect_uri`, `scope`, `state`, `nonce` (for PKCE) and more.

## Data model

There are many models in masks beyond clients, actors, and tokens, but they are
worth the most attention.

### Clients

Clients represent consumers of the masks server. Each client will end up with
subtly different configuration, depending on the authentication requirements,
level of access, and preferred look and feel.

<Aside title="An important example...">
  _**Internal** clients_ expose tokens via cookies and the session, where other
  types would expose authorization codes, access tokens, or ID tokens (as JWTs)
  in the redirect URL.
</Aside>

Take a look at the `clients.yml` configuration for a full list of configuration
options for a client. Most options can be changed dynamically by managers as well.
